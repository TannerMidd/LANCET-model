Quick start

# 1. verify the download, then the bundle
certutil -hashfile lancet-v0.2.0-nano-cpu-int8.zip SHA256
python verify_bundle.py --strict

# 2. install three pinned CPU dependencies
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 3. classify (JSON lines in, JSON lines out)
$env:OPENBLAS_NUM_THREADS = '1'
'{"command": "terraform destroy -auto-approve", "shell": "bash"}' |
  .\.venv\Scripts\python.exe classify.py --model model

  • Python 3.12 with NumPy, tokenizers and ONNX Runtime CPU. No PyTorch, no GPU, no API key.
  • Keep one process running and stream commands to it; the model loads once.
  • Commands are read as text and never executed.
  • On macOS or Linux, use .venv/bin/python. Those platforms were not benchmarked.
  • If you clone instead of downloading the ZIP: install Git LFS, run git lfs pull, and use bundle/.

How it was trained

Nano starts from LANCET V5 (Salesforce CodeT5-small) and is fine-tuned with class-balanced sampling. Its new labels come from documentation written by people, not from another model's opinions:

  • tldr-pages: each example command's one-line description sets the label. "Delete a specific pod" becomes risky; "List all volumes" becomes benign; ambiguous wording is dropped.
  • AWS botocore: the operation verb sets the label. Delete*, Terminate*, Revoke* and secret reads are risky; List*, Describe* and Get* are benign.
  • LANCET's project-authored risky/safe pairs, plus developer commands from SWE-smith, Terminal-Bench and NL2Bash.

No language model, hosted API or human labeler produced any training label.
Development and calibration used tools held out from training.
The label rules are heuristic, with an estimated 85–90% precision on risky labels from sample reading. They were not human-adjudicated.

Limits

  • Bash only. Nano does not inspect files, fetch scripts or know the task. Other shells, invalid input, more than 8,192 bytes or more than 512 tokens return review, with no silent truncation.
  • not_flagged is not execution authorization or a safety guarantee.
  • It misses about 1 in 6 risky commands on the fresh suite; its weakest areas are infrastructure-as-code and secrets.
  • Nano starts from V5, which saw historical benchmark data. Independent acceptance and human label adjudication remain unavailable.
  • Raspberry Pi and other ARM devices are plausible at this size but untested.
